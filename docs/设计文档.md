# 城市空气质量检测小程序 —— 软件设计文档

## 1. 项目概述

### 1.1 项目背景

随着城市化进程加快，空气质量对居民健康的影响日益显著。本系统旨在通过微信小程序平台，为用户提供实时空气质量监测数据查询、历史数据分析、设备管理等功能，帮助用户随时掌握周围空气环境质量。

### 1.2 项目目标

- 为普通用户提供直观的空气质量查询界面
- 实现多设备统一管理，支持设备绑定与解绑
- 提供历史数据分析与可视化能力
- 支持告警阈值设置，异常情况及时通知

### 1.3 适用范围

本系统适用于城市居民、环保爱好者、科研人员等群体，用于实时监测和分析空气质量数据。

## 2. 系统架构

### 2.1 总体架构

系统采用经典的前后端分离架构：

```
┌─────────────────────────────────────────────────────────┐
│                    表现层（微信小程序）                      │
│  登录页 | 首页 | 分析页 | 地图页 | 设备页 | 设备详情页      │
├─────────────────────────────────────────────────────────┤
│                      API 接口层                           │
│          RESTful API (HTTP/JSON) 47.109.191.13:5000       │
├─────────────────────────────────────────────────────────┤
│                     业务逻辑层                             │
│    用户认证 | 设备管理 | 数据采集 | 统计分析 | 告警服务     │
├─────────────────────────────────────────────────────────┤
│                     数据持久层                             │
│          MongoDB（设备数据） + MySQL（用户信息）             │
└─────────────────────────────────────────────────────────┘
```

### 2.2 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端框架 | 微信小程序原生框架 | WXML + WXSS + JavaScript |
| 后端框架 | Node.js / Python Flask | RESTful API 服务 |
| 实时数据库 | MongoDB | 存储设备上报的实时监测数据 |
| 关系数据库 | MySQL | 存储用户信息、设备绑定关系、收藏记录 |
| 通信协议 | HTTP + JSON | 轻量级数据交换格式 |

### 2.3 MongoDB 与 MySQL 分工策略

| 数据类型 | 存储数据库 | 原因 |
|----------|-----------|------|
| 用户信息 (open_id) | MySQL | 结构化强，事务性操作 |
| 设备注册信息 | MySQL | 与用户存在关联关系 |
| 设备绑定关系 | MySQL | 多对多关系，需要事务保证 |
| 收藏记录 | MySQL | 关系型数据，频繁关联查询 |
| 实时监测数据 | MongoDB | 高频写入，结构灵活，时序数据 |
| 历史数据 | MongoDB | 数据量大，无需复杂关联 |
| 每日统计摘要 | MongoDB | 聚合计算结果，文档存储 |

## 3. 功能模块设计

### 3.1 功能模块总览

```
城市空气质量检测小程序
├── 登录模块
│   └── 微信一键登录
├── 首页模块
│   ├── 设备切换
│   ├── 实时AQI展示
│   └── 污染物数据网格
├── 数据分析模块
│   ├── 历史数据查询（6h/12h/24h/48h/7d）
│   ├── 每日统计摘要
│   └── AQI等级颜色标记
├── 地图模块
│   ├── 设备地理位置标记
│   ├── AQI等级颜色标记
│   └── 底部设备列表切换
├── 设备管理模块
│   ├── 设备列表展示
│   ├── 收藏设备置顶
│   ├── 扫码绑定设备
│   └── 手动输入ID绑定
└── 设备详情模块
    ├── 设备信息展示
    ├── 收藏/取消收藏
    ├── GPS位置更新
    ├── 告警阈值设置
    └── 设备解绑
```

### 3.2 登录模块

- **功能描述**：用户通过微信授权一键登录，后端校验后将 open_id 返回客户端，客户端持久化存储。
- **流程**：wx.login() → 获取临时 code → 请求后端 /api/login → 后端调微信 code2Session → 返回 open_id → 存入本地缓存。
- **页面**：pages/login/login

### 3.3 首页模块

- **功能描述**：展示当前选中设备的实时空气质量数据，包括 AQI 数值、等级、污染物指标（PM2.5、NO₂、SO₂、O₃）。
- **核心特性**：
  - AQI 数值根据等级动态变色（优=绿、良=黄、轻度污染=橙、中度污染=红、重度污染=紫）
  - 支持设备切换弹窗
  - 下拉刷新获取最新数据
- **页面**：pages/index/index

### 3.4 数据分析模块

- **功能描述**：查看设备的历史监测数据，支持多时间粒度切换，展示每日统计摘要。
- **时间粒度**：6小时、12小时、24小时、48小时、7天
- **统计指标**：平均 AQI、最高 AQI、平均 PM2.5
- **页面**：pages/analysis/analysis

### 3.5 地图模块

- **功能描述**：在地图上标记所有设备位置，标记颜色按 AQI 等级动态变化，底部横向列表快速切换设备。
- **页面**：pages/map/map

### 3.6 设备管理模块

- **功能描述**：展示已绑定设备列表，收藏设备置顶显示，支持扫码和手动输入两种绑定方式。
- **页面**：pages/devices/devices

### 3.7 设备详情模块

- **功能描述**：查看设备详细信息，管理收藏状态，更新设备 GPS 位置，设置告警阈值，解绑设备。
- **页面**：pages/device-detail/device-detail

## 5. API 接口设计

### 5.1 基础信息

- **Base URL**：`http://47.109.191.13:5000`
- **请求格式**：application/json
- **响应格式**：`{ "code": 200, "data": {...}, "message": "..." }`

### 5.2 接口列表

| 方法 | 路径 | 说明 | 参数 |
|------|------|------|------|
| POST | /api/login | 用户登录 | code |
| GET | /api/devices/list | 获取设备列表 | open_id |
| POST | /api/devices/bind | 绑定设备 | open_id, device_id |
| POST | /api/devices/unbind | 解绑设备 | open_id, device_id |
| PUT | /api/devices/location | 更新设备位置 | device_id, longitude, latitude |
| GET | /api/current | 获取实时数据 | device_id |
| GET | /api/history | 获取历史数据 | device_id, hours |
| GET | /api/daily_summary | 获取每日统计 | date, device_id |
| POST | /api/favorites/add | 添加收藏 | open_id, device_id |
| POST | /api/favorites/remove | 取消收藏 | open_id, device_id |
| GET | /api/favorites/list | 获取收藏列表 | open_id |
| GET | /api/status | 获取服务状态 | 无 |

### 6.2 MongoDB 数据库（设备监测数据）

#### air_quality 实时空气质量数据集合

```json
{
  "_id": ObjectId,
  "device_id": "D001",
  "aqi": 42,
  "pm2_5": 15.3,
  "no2": 0.02,
  "so2": 0.01,
  "o3": 0.05,
  "sample_time": ISODate("2026-05-14T19:30:00Z"),
  "created_at": ISODate("2026-05-14T19:30:00Z")
}
```

**索引**：{ device_id: 1, sample_time: -1 }（复合索引，按设备和时间查询）

#### daily_summary 每日统计集合

```json
{
  "_id": ObjectId,
  "device_id": "D001",
  "stat_date": "2026-05-14",
  "avg_aqi": 42.5,
  "max_aqi": 68,
  "avg_pm2_5": 15.3,
  "sample_count": 1440,
  "created_at": ISODate("2026-05-14T23:59:59Z")
}
```

**索引**：{ device_id: 1, stat_date: -1 }（复合索引）

## 7. 数据流设计

### 7.1 实时数据流

```
设备硬件上报 → POST /api/data → MongoDB 写入 → 
小程序 GET /api/current → MongoDB 查询最新一条 → 返回给前端展示
```

### 7.2 历史数据流

```
小程序 GET /api/history?device_id=X&hours=24 →
后端查询 MongoDB 最近24小时数据 → 返回给前端 → 
前端按 AQI 等级着色渲染表格
```

### 7.3 每日统计聚合流

```
每日定时任务（或实时聚合）→ 从 MongoDB 原始数据聚合 →
计算 avg_aqi, max_aqi, avg_pm2_5 →
存入 daily_summary 集合 →
小程序 GET /api/daily_summary 查询展示
```

## 8. 安全设计

### 8.1 用户认证

- 基于微信 OAuth 2.0 认证体系
- 服务端通过 code2Session 接口验证用户身份
- open_id 作为用户唯一标识，不暴露敏感信息

### 8.2 数据安全

- 前端仅展示数据，不直接操作数据库
- 所有 API 请求统一经过后端鉴权
- 小程序端关闭合法域名校验仅用于开发环境
